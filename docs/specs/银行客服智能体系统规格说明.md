# 规格说明：基于 CrewAI 的多角色银行客服智能体系统

## Problem Statement

银行客服面临大量重复性咨询（账户查询、转账、理财、信用卡、贷款、挂失、投诉），人工处理效率低、响应慢、成本高。需要一套智能客服系统，能够自动理解用户意图、检索业务知识库、按照标准流程回复客户问题，同时保证回复的准确性和合规性。

## Solution

构建基于 CrewAI 的多角色银行客服智能体集群：

1. **Triage Agent**（分诊员）作为入口，使用 Plan&Execute 模式分析用户意图并路由到对应专家
2. **Account Agent**（账户专家）和 **Financial Advisor Agent**（理财顾问）使用 ReAct 推理链路，通过 RAG 检索知识库后生成精准回复
3. LlamaIndex + Milvus Lite 构建银行业务 RAG 知识库，BGE 模型做语义向量化
4. Ollama 本地部署 Llama 3.2 作为推理引擎，数据不出境
5. FastAPI 提供 REST API，含 `/chat` 测试端点

## Implementation Decisions

### 项目结构

采用单项目结构，使用 uv 管理依赖和虚拟环境。核心模块分为四层：agents（智能体）、rag（知识库）、tools（工具）、api（接口）。

### 智能体架构

- **Triage Agent**：使用 CrewAI 的 Plan&Execute 模式，先分析用户意图制定处理计划，再执行路由
- **Account Agent / Financial Advisor Agent**：使用 CrewAI 的 ReAct 模式，循环执行「思考→调用工具→观察结果→判断是否完成」
- 三个 Agent 共享同一个 LLM 实例（Ollama Llama 3.2），通过不同的 System Prompt 区分角色能力

### RAG 流程

- 文档加载：LlamaIndex 的 DocumentReader 支持 Word（python-docx）和 Markdown 格式
- 切片策略：基于段落和标题层级的语义切片，每个切片携带所属章节上下文
- Embedding：使用 HuggingFace 集成的 BGE 模型（bge-large-zh），本地推理
- 向量存储：Milvus Lite 嵌入式部署，无需独立服务
- 检索：余弦相似度检索，返回 Top-5 相关切片，带相关性评分

### 反幻觉策略

- Prompt 中硬约束：「仅基于以下检索到的文档内容回答，如果文档中没有相关信息，请明确告知用户」
- 检索结果低于相关性阈值时，Agent 应拒绝回答并提示「暂未找到相关信息」
- 回复中标注信息来源文档名称和章节

### API 设计

- `POST /chat`：接收用户消息，返回 Agent 回复和执行过程
- `GET /health`：系统健康检查
- `POST /knowledge/upload`：上传文档到知识库（预留）
- 请求/响应使用 Pydantic 模型做数据校验

### 对话管理

- 当前会话内的对话历史保存在内存中
- CrewAI 的 memory 机制管理上下文窗口
- 不做跨会话持久化（后续可扩展）

### 部署策略

- 开发环境：`uv run` 直接启动 FastAPI + Milvus Lite（嵌入式）
- 交付物：`docker-compose.yml` 包含 API 服务 + Ollama + Milvus（Standalone 模式）
- Ollama 需预先拉取 Llama 3.2 模型

## Testing Decisions

### 测试原则

只测试外部行为，不测试实现细节。以 API 端点和模块接口为测试边界。

### 测试切分点（Seams）

| 切分点 | 测试类型 | 覆盖内容 |
|--------|----------|----------|
| API 层 | 集成测试 | /chat 端点的请求/响应格式、状态码、错误处理 |
| Triage Agent | 单元测试 | 意图分类准确性、路由决策正确性、置信度输出 |
| RAG Pipeline | 集成测试 | 文档摄入→向量化→检索→相关性评分 |
| Agent ReAct 循环 | 单元测试 | 思考→工具调用→结果校验的完整链路 |

### 测试模块

- `tests/test_api.py`：API 端点测试
- `tests/test_triage.py`：Triage Agent 路由测试
- `tests/test_rag.py`：RAG 流程端到端测试
- `tests/test_agent_react.py`：Agent ReAct 循环测试

### 测试数据

- 使用模拟银行业务文档（Word/Markdown）作为测试知识库
- 使用 mock 工具模拟银行账户操作（不连接真实银行系统）

## Out of Scope

- 真实银行系统对接（所有账户操作使用模拟数据）
- 用户认证与权限管理
- 前端界面（仅提供 API）
- 跨会话对话持久化
- 真实 Milvus 集群部署（初期使用 Lite）
- 多语言支持（仅中文）
- 合规审查 Agent（后续增强）
- 语音交互
- 短信/邮件通知渠道

## Further Notes

- Ollama + Llama 3.2 的推理速度可能成为瓶颈，需要在 prompt 长度和响应质量之间权衡
- BGE 模型首次加载需要下载权重文件（约 1.3GB），需提前准备
- Milvus Lite 数据存储在本地文件，重新启动后数据保留
- 后续可考虑增加 Compliance Agent 做合规审查，作为回复前的安全校验层
